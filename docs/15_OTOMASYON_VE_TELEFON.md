## Otomasyon

Mevcut native `automations` aracı main kataloğu ve Space Bunny'nin mevcut OpenCode CLI/MCP yolunda açıldı. Gemini'ye `jarvis_automation` eklendi: listele, oku, çalışmaları oku, oluştur, düzenle, duraklat, yeniden etkinleştir ve kaldır. Basit Live hatırlatma yönetimi başka model turu başlatmaz. Amaç, Europe/Istanbul takvimi, görev/hedef kapsamı ve seçili özel sohbet teslimi native job kaydındadır. Tek seferlik tarih açık `+03:00`, günlük/haftalık saat kullanıcı isteğiyle eşleşir.

Doğrudan genel admin RPC'si açılmadı. Native SDK'daki `dispatchSessionAutomation`, gerçek paired kullanıcı/cihazı ve native session-access sahibini doğrular; mevcut cron caller scope ve aynı cron handler/SQLite owner'ına girer. Yeni scheduler, daemon, queue, kalıcı izin deposu veya sentetik admin yoktur. Scope yalnız istek ömründedir. Başka sohbetin işi görünmez/değiştirilemez. Güncelleme ve kaldırma gözlenen native configRevision'a bağlıdır; kaldırmada da native kilit içi revision kontrolü korunur. Reconnect eski Live user statement'ını diriltmez; yazma girişimi yeni gerçek kullanıcı sözünü ve tek kullanımlık call/input kimliğini gerektirir.

**Araçlı proje işi:** Basit hatırlatma `toolsAllow: []` olarak kalır. Araçlı otomasyon yalnız açık zamanlanmış proje işi isteği ve mevcut authenticated proje kökü ile oluşturulur. Mevcut native `automations` aracı gerçek creator/final-executable-surface araç sınırını kaydeder. Host, aynı job'ın description alanına amaç, kullanıcı, proje, üst görev, gerçek kök ve araç kısıtlarını yazar; modelin description içine koyduğu sahte kapsam bu alanları belirleyemez. Bu metadata yeni bir grant değildir: native account policy/creator/tool cap yetki sahibidir; metadata yalnız JARVIS proje kısıtını daraltır. Ayrı görev/izin deposu veya scheduler yoktur.

Native cron her çalışmada kendi run context'ine o occurrence'ın job snapshot'ını ve iptal sinyalini bağlar. SDK getter'ı yalnız gerçek run kimliğinden bu snapshot'ı okur; modelin verdiği job ID/metniyle admission üretmez. JARVIS aynı native ledger ve araç denetimiyle, aynı projede o çalışmaya ait görev kaydını oluşturur. Kök her çalışmada yeniden güvenli path denetiminden geçer; başka klasöre çıkılamaz. İş düzenlenirse eski çalışma yeni revizyon yetkisi edinmez; iptal veya run sahibinin kapanışı retained kapsamı geçersizleştirir. Önceki user statement, tek işlem onayı, quick grant veya voice yetkisi yeniden kullanılmaz.

Desteklenen cap: `read/write/edit`, `jarvis_work_read/jarvis_work_note`, `jarvis_memory_search/jarvis_memory_get/jarvis_note_read`. Space Bunny yalnız mevcut `opencode/space-bunny-free` → `jarvis-opencode-main` CLI/işçi rotasında yürür; host araçlı job'a bu modeli ve boş fallback listesini yazar. Gemini'nin doğrudan SDK yönetimi basit hatırlatma olarak kalır; araçlı prompt mevcut proje görevinin Space Bunny/OpenCode yolunda hazırlanır. Shell/script/stream, webhook, force-run, otomatik dış gönderim/ödeme, GUI quick grant ve Full access kodlama işçisi seçimi bu cap ile açılmaz; bunlar için yeni gerçek kullanıcı işlemi gerekir. Bu sınır gizli bir hazır özellik olarak sunulmaz.

Native `current` + `announce`, sonucu ilgili özel sohbetin kalıcı geçmişine yazar. PC/Gateway kapalıyken yerel iş çalışmış sayılmaz. Native `cron.skipMissedJobs` varsayılanı değiştirilmedi: false recurring catch-up yapabilir; true recurring kaçırılmış slotları atlar; tek seferlik iş kendi native catch-up kuralını kullanır. Native transient retry/backoff kuralları geçerlidir; belirsiz dış eylemin otomatik tekrarına yetki verilmez.

## Sonuç ve bildirim

Electron native cron started/finished olaylarını tüketir. Bildirimde işin **başlangıç anındaki** tanımı, çalışma kimliği/zamanı ve o çalışmanın sonucu kullanılır; sonradan düzenlenen job'ın yeni revizyonuna eski sonuç atanmaz. Admission snapshot yoksa eski sonucu yeni bildirim gibi sunmak yerine native geçmişte bırakır. Başarı/teslim belirsizliği başarı sayılmaz.

Sonuç kaydı native sohbet/run geçmişindedir; `ScheduledResults` yalnız geçici görünüm/bildirim projeksiyonudur. PC sesi zaten açık, aynı sohbette, susturulmamış ve uygun boşluktaysa mevcut 12 context yolu kullanılır. Ses kapalı/susturulmuş ve Electron açıkken kısa sessiz Windows bildirimi gösterilir; tıklama ilgili sohbeti açar. Bildirim görüşme, capture, mikrofon, oynatma veya unmute başlatmaz. Electron kapalıyken kayıt native geçmişte kalır; reconnect'te eski çalışma yeni tamamlanmış gibi duyurulmaz.

## Aynı web Control UI ve cihaza yerel ses

`native/openclaw/talk-browser-adapter.mjs`, 11–13 browser Talk uyarlamasının tek kaynak sahibidir; masaüstü bundle'ı ve native Control UI aynı uyarlamayı kullanır. `shared/voice-decisions.ts`, görev bağlama ve bounded host context kodu ortaktır. Telefon için yeni app/server/hafıza veya PC ses köprüsü yoktur. Paylaşılan browser modüllerinde Electron/preload/Node API bulunmaz.

Telefonun açık kullanıcı eylemi kendi çağrısı için bir kez tüketilir; bu yetki RPC'ye/Git'e/persistent storage'a veya diğer cihaza taşınmaz. HTTPS/secure context ve tarayıcının gerçek mikrofon izni gerekir. Native Google Live sağlayıcı/model/transport seçimi korunur; relay/başka modele fallback yoktur. Kamera kapalıdır. Sekme arka plana/kilit ekranına giderken bu cihazdaki görüşme kapatılır ve sınır gösterilir; tekrar açmak bu cihazdaki yeni kullanıcı eylemini gerektirir. Kesintisiz arka plan sesi vaat edilmez. Native Talk kapanışının bu çağrıdan başlayan işe etkisi önceki kararla aynıdır.

Yazılı girişler aynı main/session/project üzerinde mevcut scope.bind ve work.start yolunu kullanır; mikrofon açmaz. Başka sohbeti seçmek işi/sesi uzaktan başlatmaz. Açık dosya kapsamı için kullanıcı `Çalışma klasörü: C:\\somut\\klasör` satırını talimatının başına koyabilir; bu alan native host yol korumalarından geçer. Görünüm/workContext tek başına dosya yetkisi sayılmaz.

JARVIS native web istemcisinde reconnect outbox yeniden gönderimi ve timer retry kapatıldı. Denenmiş input ID'leri yalnız bu sekmenin metadata kaydında tutulur; transcript/token/voice grant tutulmaz. Sonuç belirsizken yeni gönderim yapılmaz; mevcut durum/döküm/sonuç okunur. Aynı kullanıcının paired cihazları aynı pending isteği görebilir; karar mevcut native registry'de ilk çözülene aittir. Sesli karar yalnız gerçekten sunulmuş sorudan sonraki yeni mikrofon girdisine bağlıdır; aktif sunum bu cihazın voiceSessionId'sini gösterir. Modeller resolver almaz; ödeme olumlu kararı manuel kalır.

## Tailscale

`scripts/jarvis-mobile-config.mjs` hesabın Running olmasını, cihazın kendi özel MagicDNS adını ve boş Serve/Funnel yapılandırmasını ister. Mevcut route aynı Gateway'e yönelse bile silinmez/benimsenmez; çakışmada durulur. Gerçek profile daha önce uygulandı: loopback/token/device pairing korundu, `allowTailscale=false`, managed Serve ve yalnız seçili özel HTTPS origin eklendi. Genel trusted proxy, identity-header auth veya Funnel açılmadı. Eski config profil altında yedeklidir; token URL/log/Git'e yazılmadı.

Her iki cihazda kullanıcı tailnet hesabıyla giriş yapar. Gateway başlatılmadan önce `node scripts/jarvis-mobile-config.mjs` ön kontrolü kullanılır; mevcut route varsa etkisi açıklanmadan devralınmaz. Gateway hazır olduğunda normal native başlatma Serve claim'ini açar. Token telefon Control UI bağlantı alanına elle girilir ve telefon cihazı native pairing ile yetkilendirilir. Bu çalışmada Gateway/Serve başlatılmadı veya route açılmadı. FURY mobile.ps1 kullanılmadı.
